Memory Systems

Caches, locality, virtual memory, page tables, MMU, TLB, coherence and consistency.

Present in your uploaded filesMain focus

Core idea

A processor's memory system balances speed, capacity, address translation, sharing and protection.

How to use this page

Cache coherence concerns agreement among cached copies of a memory location. Memory consistency defines the ordering rules observed by memory operations. They are related, but not interchangeable. This page is an organized prototype/reference; the uploaded files remain the detailed source material for the concepts already covered there.

1. Memory basics: UMA and NUMA

Memory stores instructions and data used by a processor and operating system. How memory is connected affects both latency and system design.

UMA · Uniform Memory Access

Processors have approximately the same memory-access latency to shared memory.

NUMA · Non-Uniform Memory Access

Memory is arranged in nodes. Local memory is generally lower latency than memory attached to another node.

2. Virtual memory, pages and address translation

A virtual address is used by software. A physical address identifies a location in the physical address space. Virtual pages map to physical page frames; the offset within a page remains unchanged during ordinary translation.

Worked example from your README

For a 4 KiB page, the page offset is 12 bits because 4,096 = 2¹². If virtual address 0x1234 maps to a physical frame with base 0x8000, then the offset is 0x234 and the illustrative physical address is 0x8234.

3. Page tables and the MMU

  • Page tables record virtual-page to physical-frame mappings and attributes.
  • The operating system creates/manages mappings; the MMU performs hardware translation and relevant permission checks.
  • Multi-level page tables split lookup into levels and can avoid allocating lower-level tables for unused address-space regions.
  • A missing mapping or disallowed access may cause an exception/page fault for software to handle.

4. TLB · Translation Lookaside Buffer

The TLB caches recently used translations and related permission information.

OutcomeMeaning
TLB hitA suitable translation is cached, avoiding a page-table walk for that access.
TLB missThe translation is not cached; hardware or software obtains it another way.
Page faultThe mapping is missing or the access violates applicable rules; a TLB miss is not automatically a page fault.

5. Cache coherence

Coherence concerns how multiple cached copies of a memory location are kept consistent with writes. Protocols such as MESI are common examples, but the specific protocol depends on the design.

6. Memory consistency

Consistency defines the ordering rules that govern how memory operations from different processors/cores may be observed. A system can maintain per-location coherence while still allowing different legal global orderings.

Remember the distinction

Coherence asks, “Do cores agree on the value/order of writes to one location?” Consistency asks, “Which ordering of memory operations is allowed across locations?” This is a conceptual shorthand; formal models define the exact rules.

7. RISC-V connections

  • RISC-V virtual-memory support depends on the implemented privilege/translation features. Your notes mention Sv39 as a three-level scheme with 4 KiB base pages.
  • SFENCE.VMA is used for relevant address-translation synchronization and invalidation after certain mapping changes.
  • Physical protection and virtual-memory page permissions are separate mechanisms that can interact.

Quick revision

  • Virtual address ≠ physical address.
  • The page offset normally remains unchanged during translation.
  • The TLB caches translations; the MMU performs translation/protection work.
  • A TLB miss does not necessarily mean a page fault.
  • Coherence and consistency solve different problems.
