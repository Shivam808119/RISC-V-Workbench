Memory & Hardware Security

Memory protection, privilege levels, PMP, side channels, speculative execution and defences.

Present in your uploaded filesMain focus

Core idea

Security is layered: privilege boundaries, memory permissions and implementation-specific protections help limit access, while side-channel defences address information leaked by hardware behaviour.

How to use this page

RISC-V PMP controls access to physical address regions. Page-table permissions govern virtual-memory accesses where translation is active. Exact behavior depends on architecture, privilege mode and platform. This page is an organized prototype/reference; the uploaded files remain the detailed source material for the concepts already covered there.

1. What memory protection controls

Memory protection defines which code can access a region and which operations it can perform. Your notes identify read, write and execute permissions.

PermissionMeaningExample of a violation
R · ReadRead data or instructions from a region.Read from a region without read permission.
W · WriteModify data in a region.Write to a read-only page.
X · ExecuteFetch and execute instructions from a region.Execute from a non-executable region.

2. RISC-V privilege modes

  • M-mode (Machine): highest standard privilege level; often used by low-level firmware.
  • S-mode (Supervisor): commonly used by an operating-system kernel.
  • U-mode (User): commonly used by applications.

Privilege modes control access to privileged operations and interact with memory protection. The exact execution environment depends on the implementation.

3. PMP · Physical Memory Protection

PMP controls access to physical address regions using address and configuration information. Its permissions include read, write and execute. The precise behavior depends on matching entries, access type, privilege mode, entry configuration and architectural rules.

Important distinction

PMP is not a replacement for virtual-memory page tables. Page tables govern virtual mappings and page permissions when translation is active; PMP defines physical-region access rules. Avoid assuming PMP blocks every access identically in every privilege mode.

4. A protection failure example

  1. A U-mode application tries to write to a virtual page whose page-table permissions allow reading but not writing.
  2. The applicable translation and permissions are checked.
  3. The prohibited write does not complete and the processor raises an appropriate page fault.
  4. The operating system handles the fault, for example by reporting an error or terminating the process.

5. Side channels & hardware security

Your security slide deck covers timing, cache-timing attacks, speculative execution, Spectre/Meltdown, physical channels and defence trade-offs.

  • A side channel is unintended information leakage through time, power, electromagnetic behavior or shared microarchitectural state.
  • Constant-time code aims to avoid secret-dependent timing behavior.
  • Cache partitioning/flushing, speculation controls and other mitigations can reduce risk but may have costs.
  • Threat models matter: an attacker who shares a machine differs from one who physically possesses a device.

Quick revision

  • Memory protection limits allowed accesses; it does not mean all memory is inaccessible.
  • R/W/X describe read, write and execute access.
  • Privilege mode, page-table permissions and PMP are related but distinct.
  • Side channels can leak secrets even when the intended algorithm is sound.
