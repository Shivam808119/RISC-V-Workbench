Overview / Cores

Ten cores, one question: what can leak?

Every core page has three steps: what the core is, which memory it uses, and which attacks it stops. The pattern is simple: the more a core does to be fast, the more it can leak.

The feature is the leak. Caches, branch predictors and shared buffers are what make a core fast, and they are also what attackers read.

Tiny cores

Almost nothing to leak.

SERV

The smallest complete RISC-V core. It works on one bit at a time, so a 32-bit add takes 32 clock cycles.

PicoRV32

A small 32-bit core that runs each instruction as several steps on one shared set of hardware. One readable Verilog file.

In-order pipelines

One instruction at a time, in program order.

Ibex

A small 2–3 stage in-order core built to protect secrets even when an attacker holds the chip. It is the CPU inside OpenTitan.

CV32E40P

A 4-stage core with DSP and machine-learning extras, formerly PULP RI5CY. Heavily verified for industry use.

Rocket

The reference 5-stage in-order 64-bit core. It boots Linux and is the base of the Chipyard and Rocket Chip generators.

SweRV EH1 (VeeR)

A 9-stage, dual-issue in-order 32-bit core with ECC-protected local memories, aimed at embedded storage and networking.

VexRiscv

A plugin-built core. You choose 2–5 stages, caches, MMU and shifters, and the toolchain generates exactly that core.

Out-of-order and families

Fast, with the most speculation.

VEGA

India’s home-grown DIR-V family. It runs from a 3-stage microcontroller (ET1031) up to a 16-stage out-of-order quad core (AS4161).

BOOM v2

The Berkeley Out-of-Order Machine. It runs many instructions at once and in a different order, then commits them in order.

SonicBOOM

BOOM’s third generation. It is up to 4-wide, with a TAGE-L branch predictor and a banked non-blocking data cache.
