SERV

The core, explained

SERV exists to answer one question: how small can a real RISC-V CPU be? Its answer is to do everything one bit at a time. A single full adder and a carry flip-flop replace the wide ALU of a normal core.

Think of a calculator that does long addition one digit at a time. It is slow, but it fits in about 125–200 FPGA cells, so hundreds of cores fit on one chip.

Because each instruction takes dozens of cycles, SERV is slow. It makes up for it by being tiny, so you can put hundreds on one FPGA. It is a good fit for housekeeping jobs, many-core experiments and any design where area matters more than speed.

2

Memory it uses, and why

Memory is where speed and security meet. Here is every memory part in SERV, with the reason it is there.

Register fileStored in the FPGA’s block RAM and read one bit at a time.
Why it is here: Memory is the only place the 32 registers fit cheaply, and one-bit reads match the one-bit datapath.
Shift and address registersA few small registers inside the core hold the bits in flight.
Why it is here: Shifting bits through small registers is how SERV assembles an address and data without wide wiring.
Instruction and data busesTwo Wishbone ports go straight to memory outside the core.
Why it is here: Wishbone is simple and common, so SERV plugs into small FPGA systems easily.
Not presentNo cache, MMU, TLB or coherence. Every access goes to plain memory.
Why it is here: Every cache, tag array and MMU costs cells. SERV omits them to stay at a few hundred.
Follow one load. SERV sends the address out the Wishbone data bus, waits for the answer, then shifts the 32 bits of data into the core one per clock. Every access costs the same cycles, with no hit or miss, so the memory path has no timing to read.
3

Security it uses, and why

The attacker you can ignore is the software one: with nothing to speculate and nothing to cache, there is no shared state to probe. The attacker you cannot ignore has the chip on a bench or can run code in machine mode, because SERV has no privilege checks of its own.

StoppedPartlyExposed by the core on its own
StoppedSpectre, MeltdownThe attack: Spectre makes a core guess a wrong path and leave traces in the cache. Meltdown reads protected data before the permission check lands. Both need a core that runs ahead of itself.
What SERV does: It never guesses ahead, so there is nothing to exploit.
StoppedCache timingThe attack: The attacker times memory accesses to learn what another program touched. A fast access means the line was cached. It needs a cache that two programs share.
What SERV does: It has no cache to probe.
StoppedOperand timingThe attack: If an instruction takes longer for certain values, anyone who can time it can work backwards to the secret. Early-exit divide and variable shifts are common causes.
What SERV does: Base ALU and shift operations always take the same number of cycles.
ExposedPrivilegeThe attack: A bug or hostile program tries to touch memory that is not its own, or to run data as code. Hardware has to say no, because software cannot be trusted to.
What SERV does: Machine mode only and no PMP. Add an address-decoder firewall outside the core.
PartlyPower, glitchesThe attack: Physical attacks: reading a secret from the power trace, or glitching voltage, clock or laser so the chip skips a check. Radiation can also flip bits by accident.
What SERV does: One-bit switching gives a quiet power trace, but there is no ECC or lockstep.

Safe by being too simple to leak, and too simple to defend itself.
