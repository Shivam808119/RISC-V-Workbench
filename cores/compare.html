What the table shows

Fewer parts, fewer leaksThe cores with no caches and no speculation (SERV, PicoRV32, CV32E40P) stop every microarchitectural attack, because the shared state is missing.
Speed brings exposureBOOM and SonicBOOM have every performance feature, and the red cells that go with them.
Small does not mean secureThe tiny cores have no privilege protection. Ibex is the one that has the hardware defences as well as the simplicity.
Local memory beats cacheIbex, EH1 and CV32E40P use scratchpads instead of data caches, so timing stays the same every time.

The four attacks, in plain words

Spectre, MeltdownSpectre makes a core guess a wrong path and leave traces in the cache. Meltdown reads protected data before the permission check lands. Both need a core that runs ahead of itself. Cores that never run ahead (all in-order cores here) are immune on their data cache.
Cache timingThe attacker times memory accesses to learn what another program touched. A fast access means the line was cached. It needs a cache that two programs share. No cache means no signal.
Timing leaksIf an instruction takes longer for certain values, anyone who can time it can work backwards to the secret. Early-exit divide and variable shifts are common causes.
PrivilegeA bug or hostile program tries to touch memory that is not its own, or to run data as code. Hardware has to say no, because software cannot be trusted to.
Fault, powerPhysical attacks: reading a secret from the power trace, or glitching voltage, clock or laser so the chip skips a check. Radiation can also flip bits by accident.

Four ways to organise memory

This is the real dividing line between the cores. Moving down the list buys speed and costs safety.

1 · No memory systemSERV and PicoRV32 talk straight to memory. They are the simplest and slowest, and nothing in them can leak through cache or prediction.
2 · Local scratchpadIbex, CV32E40P and SweRV EH1 use fast on-chip RAM instead of a data cache. Timing is fixed and ECC is easy to add. The cost is that software must place its data by hand.
3 · Cached, in orderRocket, VexRiscv and the in-order VEGA cores use caches and virtual memory but never run ahead. Fast and fairly safe, with cache timing as the main exposure.
4 · Cached and speculativeBOOM, SonicBOOM and the out-of-order VEGA models fetch ahead of certainty. Most performance, most attack surface.

Strengths and gaps

Biggest strengthIbex: all four defences together. SERV and PicoRV32: nothing to speculate. EH1: ECC on every local memory. Rocket: isolation with Keystone.
Biggest gapCV32E40P, SERV, EH1: no privilege layer. BOOM, SonicBOOM: Spectre and cache timing. VexRiscv: depends on how it is configured. VEGA: out-of-order security is not documented publicly.
