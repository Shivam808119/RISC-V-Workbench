SweRV EH1 (VeeR)

A 9-stage, dual-issue in-order 32-bit core with ECC-protected local memories, aimed at embedded storage and networking.

Instruction setRV32IMC + bit-manip
Pipeline9 stages, 2-wide
PrivilegeMachine mode only
MemoryICCM + DCCM, ECC

The core, explained

SweRV EH1, now called VeeR EH1, was open-sourced by Western Digital for its storage controllers. It issues two instructions per cycle, but always in program order.

It issues two instructions per cycle, in order. Its fast memory is on-chip RAM that software addresses directly, not a cache.

Its design choice is to skip a data cache and give the core fast local RAM instead. Software gets predictable timing and the RAM gets strong error correction, which suits products that run for years without a reset.

2

Memory it uses, and why

Memory is where speed and security meet. Here is every memory part in SweRV EH1 (VeeR), with the reason it is there.

Register file4 read and 3 write ports to feed two instructions per cycle.
Why it is here: Four read ports let two instructions each read two operands every cycle.
ICCM4–512 KB instruction RAM with ECC, plus an optional ECC instruction cache.
Why it is here: Code lives in ICCM so fetch never misses. The optional cache covers external code.
DCCM4–512 KB, 8 banks, ECC with auto-scrub. There is no data cache.
Why it is here: Fixed-latency data RAM replaces a data cache. ECC protects it from soft errors.
Load-store unitStore buffer with write coalescing, and side-effect loads are gated.
Why it is here: The store buffer merges writes, so a slow bus does not stall the pipeline.
MRAC and AXIRegion attributes, AXI4 masters, and a DMA slave port into the local memories.
Why it is here: Region attributes mark device space as not safe to speculate on. AXI connects the core to the SoC.
Follow one load. The address decoder sends it to the DCCM, one of 8 banks. The bank returns data with a 7-bit ECC code, and any single-bit flip is corrected and written back (scrubbed). There is no data cache, so timing does not depend on earlier accesses.
3

Security it uses, and why

EH1 protects data against hardware faults and timing, which suits storage and networking controllers. It has no privilege levels, so keeping a rogue DMA master out of the ICCM and DCCM is the SoC’s job.

StoppedPartlyExposed by the core on its own
StoppedData-cache attacksThe attack: The attacker times memory accesses to learn what another program touched. A fast access means the line was cached. It needs a cache that two programs share.
What SweRV EH1 does: No data cache, and the DCCM is plain addressed SRAM.
StoppedSpectre, MeltdownThe attack: Spectre makes a core guess a wrong path and leave traces in the cache. Meltdown reads protected data before the permission check lands. Both need a core that runs ahead of itself.
What SweRV EH1 does: In order, and side-effect loads on wrong paths are blocked by MRAC.
StoppedSoft errors, bit flipsThe attack: Physical attacks: reading a secret from the power trace, or glitching voltage, clock or laser so the chip skips a check. Radiation can also flip bits by accident.
What SweRV EH1 does: 39-bit SECDED ECC fixes single-bit errors and scrubs them.
StoppedInstruction timingThe attack: If an instruction takes longer for certain values, anyone who can time it can work backwards to the secret. Early-exit divide and variable shifts are common causes.
What SweRV EH1 does: Fixed one-cycle ALUs and a fixed three-cycle multiplier.
ExposedPrivilege, DMAThe attack: A bug or hostile program tries to touch memory that is not its own, or to run data as code. Hardware has to say no, because software cannot be trusted to.
What SweRV EH1 does: Machine mode only. A bus firewall must guard the DMA port.

Deterministic memory and strong ECC, but no privilege layer.
