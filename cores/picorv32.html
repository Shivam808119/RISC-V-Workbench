PicoRV32

A small 32-bit core that runs each instruction as several steps on one shared set of hardware. One readable Verilog file.

Instruction setRV32IMC
StyleMulticycle state machine
PrivilegeFlat, trap pin

1

The core, explained

PicoRV32 is the practical small core. It keeps a normal 32-bit datapath, but a state machine walks each instruction through fetch, decode, read, execute and write, using the same ALU every time.

It takes about 3–6 cycles per instruction and runs at a high clock. Heavy jobs such as multiply or crypto can be handed to a co-processor over the PCPI port.

That keeps the logic small and the clock fast. Its single Verilog file, its choice of buses and its PCPI co-processor port make it one of the most reused cores in hobby and industrial FPGAs.

2

Memory it uses, and why

Memory is where speed and security meet. Here is every memory part in PicoRV32, with the reason it is there.

Register fileA plain array of 32 (or 16) registers, built from flip-flops or RAM.
Why it is here: A flat array is the cheapest way to hold registers, and FPGA tools map it to RAM.
Native memory busOne shared valid/ready bus for code and data. A flag marks instruction fetches.
Why it is here: One bus for code and data means little wiring and a very small core.
Look-ahead busAnnounces the next address early so memory can answer faster.
Why it is here: Telling memory the next address early hides its delay without adding a cache.
AdaptersAXI4-Lite and Wishbone wrappers. No caches, no MMU.
Why it is here: Wrappers let the core join AXI or Wishbone systems without redesign. Skipping caches keeps timing simple.
Follow one load. The state machine puts the address on mem_valid, waits for mem_ready, latches the data, and only then moves on. Code and data share this one bus, and the mem_instr flag says which one is being fetched.
3

Security it uses, and why

Since one instruction runs at a time, software attacks on the core itself are off the table. Real risks are operand timing in the serial shifter and divider, and any program that can write code into memory it then executes.

StoppedPartlyExposed by the core on its own
StoppedSpectre, MeltdownThe attack: Spectre makes a core guess a wrong path and leave traces in the cache. Meltdown reads protected data before the permission check lands. Both need a core that runs ahead of itself.
What PicoRV32 does: Only one instruction exists in the core at any moment.
StoppedCache timingThe attack: The attacker times memory accesses to learn what another program touched. A fast access means the line was cached. It needs a cache that two programs share.
What PicoRV32 does: No caches, so every access takes a predictable path.
PartlyOperand timingThe attack: If an instruction takes longer for certain values, anyone who can time it can work backwards to the secret. Early-exit divide and variable shifts are common causes.
What PicoRV32 does: The default serial shifter and divider leak through cycle counts. Choose the barrel shifter and fast multiplier.
PartlyCode injectionThe attack: A bug or hostile program tries to touch memory that is not its own, or to run data as code. Hardware has to say no, because software cannot be trusted to.
What PicoRV32 does: The instruction-fetch flag lets a small outside wrapper block data from running as code.
PartlyBad opcodes, glitchesThe attack: Physical attacks: reading a secret from the power trace, or glitching voltage, clock or laser so the chip skips a check. Radiation can also flip bits by accident.
What PicoRV32 does: It traps illegal and misaligned instructions. Keep crypto in a PCPI accelerator and add an outside watchdog.

Easy to audit and free of speculation, but it needs help from the system around it.
